# Client onboarding API

Этот модуль принимает анкеты из Students Life без предварительной регистрации пользователя.

## Публичный сценарий

1. Мобильное приложение хранит черновик только на устройстве.
2. Готовая анкета отправляется `POST /api/client/v1/onboarding/submissions/`.
3. Сервер возвращает `public_id` и одноразово показывает `access_token`. Приложение хранит оба значения в защищённом локальном хранилище.
4. Статус проверяется через `GET /api/client/v1/onboarding/submissions/{public_id}/` с заголовком `X-Onboarding-Token`.
5. Если менеджер запросил исправления, полная исправленная анкета повторно отправляется `PUT` на тот же адрес с тем же заголовком.

Для анкеты абитуриента обязательны 3–5 разных ВУЗов и 3–6 разных программ. Программа должна относиться к выбранному ВУЗу. Предварительная анкета школьника не требует выбора ВУЗов.

## Проверка менеджером

Список анкет доступен сотрудникам через `GET /api/v1/onboarding/submissions/`. Решение отправляется в `POST /api/v1/onboarding/submissions/{id}/review/`:

```json
{
  "decision": "approve | request_changes | reject",
  "comment": "Комментарий для клиента"
}
```

Одобрение выполняется транзакционно и повторяемо: повторное решение `approve` не создаёт второго клиента. После одобрения создаются CRM-клиент, каноническая анкета, один `Application` на каждый выбранный ВУЗ и последовательный `SL-ID`.

Интеграция с Google Sheets, создание клиентских учётных данных и TMmail вынесены в следующие этапы. Они должны запускаться через идемпотентные фоновые операции после одобрения, когда будет утверждён контракт таблицы и сервисов.
