# Инструкция по заполнению базы ManagerSL

## Актуальные разделы админки

Для ежедневной работы используйте новые ERP-разделы: Организация, Сотрудники, CRM, ВУЗы и программы, Услуги, Финансы, Документы, Рабочий день, Проекты, База знаний, Календарь и Уведомления.

Старые приложения `clients`, `leads`, `catalog`, `services`, `analytics`, `documents`, `tasks`, `timetracking` оставлены в проекте для миграций и совместимости, но в новой работе их использовать не нужно. В админке они скрываются от обычных staff-пользователей; при необходимости суперадминистратор может открыть их как архивные данные.

Клиентов и лидов создавайте в новом CRM, ВУЗы и программы — в `apps.education`, услуги — в `apps.erp_services`, документы и шаблоны — в `apps.erp_documents`.

## 1. Вход в админку

Админка доступна по адресу `/admin/`. Доступ должны иметь только superuser, staff и сотрудники, которым явно разрешено управление системой. Обычные сотрудники работают через `/portal/`.

## 2. Порядок первичной настройки

1. Создайте компанию в разделе «Организация / Company».
2. Создайте офисы и обязательно привяжите каждый офис к компании.
3. Создайте отделы.
4. Создайте должности.
5. Создайте роли сотрудников.
6. Создайте пользователей.
7. Создайте EmployeeProfile для каждого пользователя.
8. В профиле сотрудника укажите компанию, офис, отдел, должность, роль и дату рождения.

Если сотруднику не создать EmployeeProfile, портал не сможет правильно подставлять компанию, офис, рабочий день и права доступа.

## 3. Как заполнить ВУЗы

1. Создайте страну.
2. Создайте город и привяжите его к стране.
3. Создайте валюту и укажите курс к USD.
4. Создайте ВУЗ.
5. Добавьте программы ВУЗа.
6. Добавьте стоимость программ.
7. Добавьте intakes / наборы.
8. Добавьте требуемые документы.
9. Добавьте контакты ВУЗа.

Если добавили ВУЗ, обязательно добавьте ему хотя бы одну программу. Если добавляете стоимость, обязательно выберите валюту.

## 4. Как заполнить услуги

1. Создайте категорию услуги.
2. Создайте услугу.
3. Укажите цену для клиента.
4. Укажите себестоимость.
5. Выберите валюту.
6. Отметьте, активна ли услуга и видна ли она сотрудникам.

Услуги можно добавлять и через портал: `/portal/services/`.

## 5. Как добавить клиента

Минимально нужны ФИО и телефон или email. Остальные поля необязательные, но полезны для документов:

- паспортные данные нужны для договоров и заявлений;
- адрес регистрации нужен для договоров;
- данные родственника нужны для отдельных документов;
- интересующая страна, ВУЗ и программа помогают менеджеру вести клиента.

Обычный сотрудник в портале создаёт клиента только на себя и свой офис. Администратор может выбрать менеджера и офис вручную.

## 6. Заявки с сайта

Старый endpoint `/api/leads/create/` сохранён. Фронтенд сайта должен передавать `X-API-KEY`, а ключ хранится только в `.env` как `LEADS_API_KEY`.

Новые заявки попадают в новую CRM как «Потенциальные клиенты» в `/portal/incoming-leads/`. Менеджер нажимает «Взять», после чего заявка закрепляется за ним и его офисом. Если менеджер взял заявку случайно и клиент ещё не создан, он может нажать «Вернуть», и заявка снова станет свободной.

Лиды не удаляются физически из портала. Их нужно переносить в архив кнопкой «В архив». Обычный сотрудник может архивировать только свои лиды, администратор может архивировать и восстанавливать любые лиды. В карточке лида видны данные с сайта, история действий и, для администратора, техническая информация: IP, User-Agent, Referer, Origin и API source.

## 7. Как создать шаблон документа

1. Откройте раздел документов в админке.
2. Создайте DocumentTemplate.
3. Загрузите DOCX-шаблон.
4. Укажите тип документа и описание.
5. Добавьте поля DocumentTemplateField через inline-блок внизу формы. JSON вручную заполнять не нужно.
6. Для каждого поля укажите название, `key`, `jinja_key`, источник данных, подсказку и обязательность.
7. Используйте Jinja-переменные в DOCX, например `{{ client.full_name }}`, `{{ client.phone }}`, `{{ client.passport_inter_num }}`, `{{ application.university_name }}`, `{{ manager.first_name }}`, `{{ company.name }}`.
8. Настройте, нужно ли подтверждение администратора.
9. Настройте правила печати StampRule, если нужен PDF с электронной печатью.

В StampRule загрузите изображение печати, укажите размер в миллиметрах, позицию, прозрачность, а при необходимости включите водяной знак, текст/изображение, позицию и размер. Если печать не настроена, портал покажет понятную ошибку: «Для этого шаблона не настроена электронная печать».

Если шаблон не содержит DOCX-файл или обязательные поля не заполнены, портал покажет понятную ошибку вместо 500.

## 8. Как генерировать документы

1. Откройте клиента в `/portal/clients/`.
2. Нажмите «Создать документ».
3. Выберите шаблон.
4. При необходимости выберите заявку или сделку.
5. Проверьте данные.
6. Создайте DOCX.
7. DOCX без печати можно скачать сразу.
8. PDF с печатью доступен только после подтверждения администратора в `/portal/approvals/`.

## 9. Как работать с финансами

Валюта системы: USD.

1. Создайте сделку и выберите услугу из базы или напишите название вручную.
2. Добавьте платёж по сделке.
3. Добавьте доход, если нужно зафиксировать поступление отдельно.
4. Доход после создания имеет статус «Ожидает подтверждения».
5. Администратор подтверждает доход в `/portal/approvals/`.
6. После подтверждения доход учитывается в статистике и менеджеру начисляется комиссия 5%.
7. Расходы через портал сразу учитываются в расходах.

Повторное подтверждение дохода не начисляет комиссию повторно.

## 10. Как работать с проектами

1. Создайте проект в `/portal/projects/`.
2. Система автоматически создаст раздел «Основные задачи».
3. При необходимости добавьте дополнительные разделы.
4. Создайте задачу из карточки проекта.
5. Укажите исполнителя, дедлайн, статус и приоритет.
6. В карточке проекта можно добавлять комментарии, чек-листы и файлы к задачам.

Проекты могут создавать все сотрудники. Удалять проекты может только администратор.

## 11. Как работать с базой знаний

1. Создайте папку.
2. Внутри папки создайте вложенные папки или статьи.
3. В статье можно хранить инструкции, текст для копирования, файлы и ссылки.
4. Поиск работает по названию, описанию и тексту статьи.
5. Обычные сотрудники могут создавать и редактировать материалы.
6. Удалять папки и статьи может только администратор.

## 12. Как работать с календарём и отчётами сотрудников

1. Откройте `/portal/calendar/`.
2. Нажмите на нужный день, чтобы увидеть мероприятия, задачи, дни рождения и важные даты заявок.
3. Создайте событие: укажите название, дату, время, описание, офис и видимость.
4. Обычный сотрудник может создавать личные события и события своего офиса.
5. Администратор может создавать события для офиса или всей компании, редактировать и удалять события.
6. Отчёты сотрудников администратор смотрит в `/portal/employee-reports/`.
7. На странице отчётов есть фильтры по периоду, дате, сотруднику и офису.
8. Рабочие старты и отчёты не выводятся в календаре, чтобы не перегружать его. Их смотрят на странице `/portal/workday/` и в `/portal/employee-reports/`.

## 13. Как пользоваться страницей рабочего дня

Обычный сотрудник на `/portal/workday/` видит свой текущий день, свои последние отчёты и только свою историю start/report/close. Блок «Сотрудники сегодня» показывает краткий статус сотрудников доступного офиса.

Администратор видит сотрудников компании, кто начал день, кто не начал, кто отправил отчёт и кто закрыл день. Историю рабочего дня администратор может фильтровать по офису, сотруднику и датам.

## 14. Что проверять после заполнения

- У каждого офиса есть компания.
- У каждого сотрудника есть EmployeeProfile.
- У каждого ВУЗа есть программы.
- У каждой программы есть валюта и стоимость, если она нужна для продаж.
- У каждой услуги есть категория, цена, себестоимость и валюта.
- У шаблона документа загружен DOCX.
- Для PDF с печатью создан активный StampRule.
- У входящих заявок назначается менеджер через «Взять ответственность».

## 15. Что изменилось в текущей админке

Обычные staff-пользователи должны работать в новых разделах: Организация, Сотрудники, CRM, ВУЗы и программы, Услуги, Финансы, Документы, Рабочий день, Проекты, База знаний, Календарь и Уведомления. Старые приложения `catalog`, `clients`, `leads`, `services`, `analytics`, `documents`, `tasks` и `timetracking` оставлены как архив и для совместимости миграций. Их не нужно использовать для новых данных.

При добавлении ВУЗа теперь открывается одна удобная страница: основные данные, контакты, описание, изображения, программы, требуемые документы и контакты ВУЗа находятся рядом. Стоимость программ добавляется после сохранения ВУЗа в разделе «Стоимость программ»: выберите программу, валюту и суммы.

При добавлении шаблона документа JSON вручную заполнять не нужно. Используйте inline-блок `DocumentTemplateField` для переменных шаблона и inline-блок `StampRule` для электронной печати и водяного знака. Если для шаблона нет активной печати, PDF с печатью не создаётся и пользователь видит понятную ошибку.

Финансы в портале упрощены: основная валюта системы — USD. Доходы, расходы, платежи, балансы и комиссии считаются в USD. Доход после создания ожидает подтверждения администратора; расход учитывается сразу; комиссия менеджера 5% начисляется только после подтверждения дохода.

Администратор может создавать уведомления в `/portal/notifications/create/`: одному сотруднику, офису или всем активным сотрудникам. Обычные сотрудники только читают свои уведомления.
