# Telegram-учёт рабочего дня

ManagerSL отправляет в одну служебную Telegram-группу:

- `#приход` — первый вход сотрудника в ManagerSL в рабочий день;
- `#уход` — ручное завершение рабочего дня;
- `#автозакрытие` — завершение системой в 18:00;
- `#неявка` — сотрудник не входил и рабочий день не был начат;
- `#недельный_отчёт` — единая сводка по офисам и сотрудникам за понедельник–субботу.

Повторное открытие страниц не создаёт повторный приход. Каждое событие имеет уникальный ключ в базе. Неотправленные сообщения повторяются фоновой задачей, но уже успешно отправленные сообщения второй раз не уходят.

## Настройка production

Добавить бота в закрытую группу и разрешить ему отправлять сообщения. В `.env` сервера указать:

```dotenv
ATTENDANCE_TELEGRAM_ENABLED=True
ATTENDANCE_TELEGRAM_BOT_TOKEN=<bot-token>
ATTENDANCE_TELEGRAM_CHAT_ID=<negative-group-id>
ATTENDANCE_TELEGRAM_API_BASE=https://api.telegram.org
ATTENDANCE_AUTO_CLOSE_HOUR=18
ATTENDANCE_AUTO_CLOSE_MINUTE=0
ATTENDANCE_WORKDAYS=0,1,2,3,4,5
```

Если Telegram доступен серверу только через действующий relay, в `ATTENDANCE_TELEGRAM_API_BASE` используется тот же адрес relay, что и для уведомлений о новых заявках.

После изменения окружения необходимо пересоздать контейнеры `web`, `celery` и `celery-beat`, затем выполнить тестовую отправку. Токен нельзя добавлять в Git, логи или документацию.
